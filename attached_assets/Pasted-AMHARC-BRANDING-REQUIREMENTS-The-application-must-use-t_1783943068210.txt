DESIGN TOKENS

Create a central theme file containing the following tokens:

{
  "brand": {
    "black": "#000000",
    "green": "#1C8551",
    "lime": "#B6DC46",
    "white": "#FFFFFF"
  }
}

Use these values through semantic design tokens rather than hard-coding colours throughout the application.

Example semantic tokens:

{
  "backgroundPrimary": "#000000",
  "backgroundSecondary": "#FFFFFF",
  "textOnDark": "#FFFFFF",
  "textOnLight": "#000000",
  "actionPrimary": "#1C8551",
  "actionSecondary": "#B6DC46",
  "statusConnected": "#1C8551",

  "borderLight": "#FFFFFF"
}

Create the following implementation files where appropriate:

- overlay-theme.json

ACCESSIBILITY

The branding must not reduce accessibility.

Requirements:

- Maintain WCAG-compliant text contrast.
- Do not use green or lime as the sole indicator of status.
- Combine colour with text, icons or patterns.
- Use white text on black where strong contrast is required.
- Use black text on lime where appropriate.
- Validate contrast before using white text on AMHARC Green.
- Provide visible keyboard focus states.
- Ensure critical warnings are not represented only by colour.

Do not introduce additional decorative colours without approval.

Where a warning or error state requires a colour outside the AMHARC palette, use the minimum necessary supporting colour and document it as a functional accessibility colour rather than part of the AMHARC brand palette.

APPLICATION VISUAL STYLE

The visual style should be:

- Professional
- Modern
- Technical
- Sport-focused
- High contrast
- Suitable for outdoor use
- Suitable for low-light match environments
- Clear at a glance
- Free from unnecessary decoration
- Consistent across desktop, web and overlays

The operator interface should favour a dark operational theme because it will frequently be used:

- Outdoors
- At night
- In commentary positions
- Near video equipment
- During live production

Use black as the dominant background in live capture mode.

Use white for primary text.

Use AMHARC Green for primary actions and healthy connected states.

Use AMHARC Lime for live activity, active timing and selected event states.

BRANDING ACCEPTANCE CRITERIA

Branding is accepted only when:

1. Both supplied AMHARC logo assets are included in the repository.
2. The logos retain their original proportions.
3. The application uses the four canonical core colours.
4. Colours are implemented through central design tokens.
5. The Live Capture interface defaults to a dark theme.
6. The printed or report interface defaults to a light theme.
7. The AMHARC logo appears on the splash screen.
8. The AMHARC app icon is used for the Windows application.
9. Broadcast overlay templates use the AMHARC palette.
10. Stream Deck profiles use the AMHARC palette.
11. Accessibility contrast tests pass.
12. Status indicators include text or icons as well as colour.
13. No unapproved brand colours are introduced.
14. A formal BRAND_GUIDELINES.md file is created.
15. All references use the product name “AMHARC Match Capture”.
